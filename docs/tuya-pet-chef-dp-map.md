## 第一阶段控制策略

第一阶段先不接入 Tuya 云菜谱和多步骤菜谱系统，优先使用 `diy` 模式跑通 App 到机器的最小控制闭环：

```json
{
  "1": true,
  "3": "diy",
  "7": 1200,
  "9": 85,
  "102": 8,
  "108": "1",
  "107": "start"
}
```

含义：

- `1 power`: 打开设备。
- `3 mode`: 使用 `diy` 模式。
- `7 cook_time`: 计划烹饪时间，单位秒。
- `9 cook_temperature`: 烹饪温度，第一版默认 85 摄氏度。
- `102 cook_mode_power`: 功率档位，第一版默认 8。
- `108 cook_mode_speed`: 搅拌速度，第一版默认 `1`。
- `107 cook_s_p_r`: 启动/暂停/复位，启动时下发 `start`。

## 状态枚举

`status`:

- `standby`: 待机中
- `appointment`: 预约中
- `cooking`: 烹饪中
- `done`: 烹饪完成
- `pause`: 烹饪暂停
- `Add_Ingredients`: 加料中

`cook_s_p_r`:

- `start`: 启动
- `pause`: 暂停
- `reset`: 复位

## 和工厂联调时必须确认

1. 多个 DP 是否可以一次性下发，还是必须按顺序分批下发。
2. `cook_s_p_r=start` 是否必须最后下发。
3. MCU 收到 `DP7 cook_time` 后是否会按该秒数原生停止；若仍向上计时，需要工厂检查 MCU 对 DP7 的实现。
4. `cook_temperature=85` 实机是否可以稳定低温控制。
5. `cook_mode_speed` 的 `L` 与 `1-10` 分别对应什么转速。
6. `cook_mode_power=8` 的实际加热功率范围。
7. `fault` 的 `E01/E02/E03/E04/E05/E07/E08/E11` 具体故障含义。
8. 设备配网方式：EZ、AP、蓝牙辅助、扫码中支持哪些。
9. 设备复位/进入配网模式的按键方式。

## 低温烹饪流程

- 每次烹饪开始前先下发 `DP107=reset`，等待设备退出上一状态；再下发目标温度、功率、转速和 `DP7` 计划总秒数，参数下发成功后单独下发 `DP107=start`。参数和启动命令禁止放在同一个无序 Map 中，避免 MCU 先执行启动再接收时长。
- 烹饪总时长不再包含预加热：100 克读取食谱数据库 `cooking_profile.cook_minutes`，缺失时为 10 分钟；200/300/400/500/600/700/800 克依次为 15/18/21/25/29/34/39 分钟。
- App 只提供 1–8 份选择，每份固定 100 克；后端仅接受 100、200、300、400、500、600、700、800 克，其他克重拒绝启动。
- App 保存计划总秒数并使用绝对开始时间连续倒计时；启动时间从用户发起命令时记录，不能等 Tuya 云端回执后才起表。App 自己启动的烹饪以本地时钟连续显示，避免间歇上报的 DP8 让页面停顿后跳变；仅在缺少本地时钟（例如跨端恢复）时使用有效 DP8 辅助显示。`DP8=0` 不单独作为完成信号，避免旧缓存或非烹饪阶段的零值导致误判。
- App 本地倒计时达到计划时长，或设备明确上报 `DP5=done/complete` 时，只下发一次 `DP107=reset`；失败时进行一次幂等重试，并提示用户手动复位。
- 正常情况下 MCU 应根据 DP7 原生计时并停止；App 同时在计划截止时补发 `DP107=reset` 作为双重保险。App 重新进入烹饪页时会根据持久化开始时间恢复并补发复位；App 被系统杀死时的硬件侧精确停止仍必须依赖 MCU 正确实现 DP7。
- 多设备账号从食谱“一键烹饪”进入时必须先明确选择一台在线设备，不得默认向设备列表第一台发送命令；单设备账号可直接进入该设备控制页。
- 用户修改鲜食机名称时同时更新 Tuya 设备名称和 Heybo 后端设备缓存；设备唯一标识仍使用 `devId`，名称只用于展示，不参与命令路由。
