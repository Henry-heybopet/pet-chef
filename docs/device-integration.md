# 设备联动

## 目标

定义软件与宠物鲜食机设备之间的职责边界，避免 UI、后端和设备通信逻辑混在一起。

## 当前代码线索

当前仓库包含：

- `backend/`
- `api/`
- `frontend/src/components/CookingScreen.jsx`
- `frontend/src/components/RecipeMake.jsx`

这些模块可能承担设备状态展示、制作流程触发和服务端通信。

## 建议边界

- 前端：展示设备状态、烹饪步骤和用户操作。
- 后端/API：处理鉴权、设备请求、重试、超时和错误归一化。
- 设备/云平台：执行真实指令并返回状态。

## 待确认

- 设备通信是否走 Tuya/涂鸦平台。
- 当前支持哪些设备指令。
- 食谱步骤如何映射为设备动作。
- 超时、失败、断网时的用户提示规则。
- 是否需要模拟设备模式用于演示。

## 验收清单

- 可以从食谱进入制作流程。
- 可以看到烹饪状态变化。
- 接口失败时有明确提示。
- 设备超时时可以重试。
- 演示环境不依赖真实设备也能展示完整流程。
