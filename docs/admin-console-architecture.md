# Heybo 管理后台架构说明

## 为什么管理后台是必需的

Heybo Pet 同时覆盖宠物档案、鲜食机设备、食谱推荐、商品订单和医疗审核等业务域。移动端负责用户体验，但运营、客服、营养编辑和医疗审核需要一个受控入口来查看状态、处理异常、审核内容并追踪风险。

没有管理后台时，团队会依赖数据库直查、临时脚本或客服手工记录，容易出现权限边界不清、数据修改不可追踪、设备故障难定位、食谱和医疗内容审核缺少闭环的问题。后台的第一价值不是完整 CRUD，而是把关键业务对象、责任角色和优先级先收束到同一个操作面。

## 第一版做什么

第一版 admin console 采用独立的 React + Vite 应用，保持与现有 frontend 相同的基础技术栈。当前只提供静态模块总览仪表盘，不接真实后端，不引入路由、状态管理或 UI 组件库。

首版 P0 模块：

- 用户管理：查看用户账号、状态和基础风险标记。
- 宠物档案：查看宠物资料、品种、年龄、体重和推荐上下文。
- 设备管理：查看设备绑定、在线状态和 DP 数据摘要。
- 食谱管理：维护食谱库、适用条件、营养说明和烹饪参数。
- 故障日志：汇总设备异常、烹饪失败、配网失败和关键接口错误。

首版 P1 占位模块：

- 商品管理：管理食材包、耗材、设备 SKU 和上下架状态。
- 订单管理：跟踪订单、支付、履约、售后和异常状态。
- 医疗资料：管理宠物健康资料、过敏史、医嘱附件和敏感字段。
- 医生审核：审核医生资质、专业领域、合作状态和健康内容背书。

## 权限角色草案

`admin/src/adminModules.js` 定义了后台角色和模块归属，后续可作为菜单、RBAC 和接口权限的共同来源。

- 超级管理员：全局配置、权限、审计、跨模块运营。
- 运营：用户、宠物、商品、订单、内容日常维护。
- 营养/食谱编辑：食谱资料、适配标签、营养说明审核。
- 医疗审核员：医疗资料、医生资质、健康相关内容审核。
- 客服/设备支持：设备绑定状态、订单售后、故障日志跟进。

## 依赖条件

第一版只依赖 React、React DOM、Vite 和 Vite React 插件。版本与 `frontend/package.json` 保持一致，避免后台骨架引入额外复杂度。

后续进入真实业务前，需要主线程补齐以下条件：

- 后端管理 API：用户、宠物、设备、食谱、商品、订单、医疗和日志的查询接口。
- 登录与权限：管理员账号体系、RBAC、审计日志和敏感操作二次确认。
- 数据契约：各模块列表字段、详情字段、筛选项、状态枚举和错误码。
- 设备数据来源：Tuya DP 映射、设备在线状态、故障码和操作日志的稳定同步。
- 医疗合规边界：医疗资料可见性、医生资质审核材料、健康建议免责声明和数据留存策略。
- 发布方式：admin 的构建脚本是否接入根 package、部署路径、环境变量和访问域名。
