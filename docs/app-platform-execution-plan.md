# Heybo Pet App Platform Execution Plan

## 1. 总体架构

Heybo Pet App 平台分为 5 个部分：

1. App 原生能力层。
2. App 前端体验层。
3. Heybo 后端业务平台层。
4. Heybo 管理后台。
5. 数据分析与推荐系统。

核心原则：

- Heybo 账号是用户唯一可见账号。
- Tuya SDK 是设备能力层，不直接承担 Heybo 业务账号职责。
- 前端负责体验闭环，后端负责数据闭环。
- 管理后台负责运营配置和内部管理。
- 数据分析与推荐系统负责长期产品壁垒。

## 2. 五大部分职责

### 2.1 App 原生能力层

职责：

- 集成 Tuya SDK。
- 设备配网、绑定、设备列表、DP 指令下发、状态监听。
- 微信登录。
- Apple ID 登录。
- Google ID 登录。
- 微信支付、支付宝、Apple Pay、Google Pay 预留。
- Push 通知。
- 相机、相册、文件上传。
- 原生权限管理：Wi-Fi、蓝牙、定位、相机、通知。
- 原生安全存储：保存 token、会话、临时凭证。
- App 版本升级、崩溃日志、行为埋点 SDK。

第一阶段：

- Android Tuya SDK 先跑通。
- iOS Tuya SDK 后接。
- 登录和支付先做架构预留，后续接真实平台。

### 2.2 App 前端体验层

职责：

- 用户注册/登录。
- 首页。
- 宠物档案。
- 宠物食谱。
- AI 推荐食谱。
- 鲜食制作流程。
- 设备管理。
- 设备操作状态。
- 商城。
- 订单和地址。
- 喂食反馈。
- 健康追踪。
- 医疗资料上传。
- 消息中心。
- 账号设置和隐私设置。

第一阶段主链路：

```text
登录 -> 创建宠物档案 -> 推荐食谱 -> 绑定设备 -> 一键制作 -> 喂食反馈 -> 14 天健康观察 -> 推荐鲜食包
```

### 2.3 Heybo 后端业务平台层

职责：

- 用户账号。
- 登录身份。
- 家庭 household。
- 宠物档案。
- 宠物健康变化记录。
- Tuya UID 映射。
- 设备绑定记录。
- 设备操作记录。
- 食谱配置。
- AI 食谱。
- 兽医认证食谱。
- 医生处方食谱。
- 食材包商品。
- SKU、库存、价格。
- 订单和支付记录。
- 医疗资料。
- 医生审核预留。
- 文件上传。
- 通知。

当前阶段：

- 已有 JSON MVP。
- 下一阶段替换为真实数据库、真实登录、正式 token。

### 2.4 Heybo 管理后台

职责：

- 用户管理。
- 宠物档案查看。
- 设备绑定和故障日志。
- 食谱配置。
- 商品和 SKU 管理。
- 订单管理。
- 医疗资料查看。
- 医生审核工作台预留。
- 内容素材管理。
- 数据看板。

第一阶段：

- 先做管理后台骨架和模块看板。
- 不急于做完整 CRUD。

### 2.5 数据分析与推荐系统

职责：

- 用户行为埋点。
- 设备操作事件。
- 食谱选择事件。
- 商城购买事件。
- 喂食反馈事件。
- 健康变化事件。
- 故障和异常事件。
- 推荐信号提取。
- 宠物状态驱动的鲜食包推荐。
- 14 天、30 天、长期健康效果分析。

核心壁垒：

```text
宠物档案 + 食谱 + 食材包 + 烹饪参数 + 喂食反馈 + 健康变化
```

这些数据长期积累后，才能形成针对不同犬种、年龄、体型、健康状态的个性化鲜食推荐能力。

## 3.1 第一版已确认决策

截至当前版本，第一版市场验证按以下决策执行：

- 测试服务器：放在中国大陆。
- 登录方式：第一版继续使用 `mock-login`，暂不接真实短信验证码。
- 设备配网：工厂确认方向为 `AP + 蓝牙辅助`。
- 当前代码状态：Android 已有 AP/EZ 配网桥接；蓝牙辅助配网仍需补 Tuya BLE/multi-mode 原生实现。
- 商城支付：第一版同时接微信支付和支付宝；两个商户平台账号尚未开通，先完成服务端支付骨架并同步办理。
- 第一版测试 SKU：
  - 肉包：测试肉包1、测试肉包2、测试肉包3。
  - 菜包：测试菜包1、测试菜包2、测试菜包3。
  - 营养包：测试营养包1、测试营养包2、测试营养包3。
  - 组合包：组合包1-增强骨骼套餐、组合包2-美毛美肤套餐、组合包3-肠胃敏感套餐。

## 4. 外部依赖条件

### 4.1 Tuya

需要你或硬件工厂确认：

- 当前 K15/Pet Chef 固件支持的配网方式：已确认第一版按 `AP + 蓝牙辅助` 推进。
- 设备进入配网模式的按键和指示灯规则。
- PID 是否最终确定为 `ak2kofibhuvdtqip`。
- DP 点是否还有新增或删改。
- `multistep` raw 协议格式。
- 设备状态回传频率。
- 故障码含义。
- 解绑、重置、恢复出厂设置规则。

### 4.2 微信登录

需要准备：

- 微信开放平台企业认证。
- 移动应用创建。
- iOS Bundle ID。
- Android Package Name。
- Android 签名 SHA256。
- App 隐私政策 URL。
- App 用户协议 URL。

### 4.3 微信支付

需要准备：

- 微信支付商户号。
- 企业主体认证。
- App 支付产品开通。
- 商户 API 证书。
- 回调域名。
- 服务器 HTTPS。
- 商品和订单合规信息。
- 当前状态：商户号尚未申请，需先完成主体认证、移动应用审核及 App 支付开通。

### 4.4 支付宝

需要准备：

- 支付宝开放平台账号。
- 企业认证。
- App 支付应用。
- 应用私钥/支付宝公钥。
- 回调域名。
- 当前状态：开放平台应用尚未创建，需先完成企业认证、应用创建及 APP 支付签约。

### 4.5 Apple ID / Apple Pay / iOS 发布

需要准备：

- Apple Developer Program。
- App Identifier。
- Bundle ID。
- Sign in with Apple capability。
- App Store Connect App。
- 隐私政策 URL。
- 如果接 Apple Pay，需要 Merchant ID 和支付服务商。

### 4.6 Google ID / Google Play / Google Pay

需要准备：

- Google Play Developer 账号。
- Google Cloud OAuth Client。
- Android package。
- SHA-1/SHA-256 签名。
- 隐私政策 URL。
- Google Pay 商户配置。

### 4.7 短信验证码

候选：

- 阿里云短信。
- 腾讯云短信。

需要准备：

- 企业认证。
- 短信签名。
- 短信模板。
- Access Key。
- 发送频率和风控规则。

### 4.8 服务器和数据库

中国验证版建议准备：

- 域名。
- HTTPS 证书。
- 中国大陆服务器或香港服务器。
- 如果使用大陆服务器，需要 ICP 备案。
- PostgreSQL 或 MySQL。
- 对象存储：宠物照片、医疗报告、商品图片。
- 备份策略。
