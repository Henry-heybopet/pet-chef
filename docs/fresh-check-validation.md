# Fresh Check 确定性验证规则

Fresh Check 将两类指标分开处理：食材重量结构用于发现肉类、内脏、碳水、果蔬和脂肪来源比例失衡；宏量营养充足度使用食材库估算蛋白质、脂肪、碳水克数，并按每 1000 kcal 归一后与宠物生命阶段标准比较。

## 数据与评分边界

- 本地 `ingredient_library` 与 `ingredients_db.js` 按字段合并：数据库中的有效字段优先，空字段不得覆盖静态基础数据；数据库通用分类 `catalog` 不得覆盖静态库已经明确的蛋白质、内脏、碳水、果蔬或脂肪分类；未知食材才允许 DeepSeek 补充估算。
- Fresh Check 的食材识别与页面展示语言解耦。`ingredient_translations` 中已有译名的英、德、法、西、意、日、韩名称必须先映射到中文规范食材记录；`fallback` 只表示该行的功效文案可能未完整翻译，若名称已有译名仍可用于匹配。未翻译名称会与中文规范名相同并自动跳过，冲突别名也不会参与匹配。带有生熟、切法或产地说明的名称使用大小写无关的 Unicode 词边界匹配，禁止用任意子串命中。未命中别名的任意语言输入才进入 DeepSeek。
- DeepSeek 食材核验必须使用稳定 `input_id` 对齐返回项，并保留用户输入的原始食材名称用于展示；禁止依赖模型逐字返回原名称。标准分类 `protein`、`organ`、`carb`、`vegetable`、`fruit`、`fat`、`addition` 必须参与同一套确定性结构计算。
- DeepSeek 首次返回的营养或食材安全字段任一不完整（`is_food` 未确认、`dog_safety` 为 `null/uncertain`、或缺少营养值）时，只允许复核一次。两次结论冲突时采用保守合并：任何一次明确为非食物或犬类不安全都必须阻断；明确安全结论不得被另一轮的模糊结论降级。
- 食材核验服务超时、限流或返回无效结构时，记录不含食材及用户数据的错误类型，并仅显示一次“食材核验服务暂时不可用”；不得把服务异常伪装成每项食材本身的安全性不确定。服务异常结果不能用于长期喂养决策。
- DeepSeek 只负责补数据和复核说明，不能覆盖确定性风险、分数或把不确定结果判断为达标。
- 后台食谱的“100克能量密度”与 Fresh Check 共用合并后的 `ingredient_library` / `ingredients_db.js` 食材记录和逐项能量公式：每项能量为 `食材克数 × calories_per_100g ÷ 100`（逐项取整），食谱密度为 `总能量 ÷ 总食材克数`。后台按 100 克换算显示千卡，并同时展示 `kcal/g`；任何食材缺少可靠能量值时不得按 0 伪造完整结果。
- 后台食材配比展示固定为四类：动物性原料（肌肉与内脏）、淀粉类碳水、非淀粉类果蔬、其它（脂肪酸与补剂等）；每类内部按占比从高到低排序。B 全价营养包仍不计入 A 包食材分类和能量。
- 食材数据覆盖重量低于 80% 时，宏量营养结论为不确定，营养完整性和长期适宜性最高 60 分。
- B 全价营养包按每 100 克食材配 10 克，在烹饪完成后拌入，只确认数据库说明明确覆盖的维生素、矿物质、钙、磷、微量元素及必需脂肪酸项目；这些项目全部有明确来源时，才把微量营养覆盖判定为完整。营养包不计入食材总重、宏量营养、能量、食材比例或烹饪参数；说明中没有 Omega-3、鱼油、藻油、DHA、EPA 或脂肪酸时，不得推定其覆盖必需脂肪酸。
- PostgreSQL 食谱的独立 `b_pack` 字段为空或为“无”时，不得覆盖 `nutrition_snapshot.b_pack` 中的有效说明；结构化对象形式的 B 包配方必须先转换为可审计的名称、成分和剂量说明再进入覆盖判断。规范食谱两处都缺失时，按稳定食谱 ID 使用版本化静态食谱中的必配 B 包兜底；自定义食谱不得套用该兜底。
- 未知输入先判断是否为真实食物及是否适合犬类食用；非食物或犬类不安全食材直接标为危险并要求移除，不进入营养计算。
- 明确的饮用水名称（`水`、`清水`、`饮用水`、`纯净水`、`矿泉水`、`Water`）使用本地确定性事实：犬类安全、归为烹饪添加项、0 kcal、100% 水分，不提交 AI 食材安全核验。名称只允许忽略首尾空格和英文大小写后的全词匹配，禁止用“包含水字”判断，以免把水牛肉等食材误判为水。
- 未知但可食用的食材第一次未返回有效营养值时，DeepSeek 只复核一次。第二次仍为 `null` 时，页面明确提示“未查询到该食材的营养值，未计入食品营养值计算”，禁止按 0 或分类兜底值冒充已覆盖数据。
- 长期适宜性取营养完整性、结构平衡性、能量满足度、宠物适配性的共同下限，并返回当前限制项及改善建议。幼龄或特殊阶段的专业确认独立提示，不再把长期适宜性固定锁定为60分。
- DeepSeek 的食材数据补全和宏量营养复核在后台执行；页面只合并展示不重复确定性数字的一条行动建议。
- 页面将肉类等原料自身脂肪标为“含脂食材”，将鱼油等独立添加项标为“额外油脂”，避免把脂肪克数与油脂食材占比混为一谈。
- AI 推荐匹配分使用 Fresh Check 六维加权模型：食材安全性 20%、宠物适配性 15%、食谱结构平衡性 20%、营养完整性 15%、长期适宜性 10%、能量需求满足度 20%。长期适宜性仍显示限制项，但不再直接替代综合匹配分；存在红色安全风险或安全性低于 70 分时，推荐分最高为 49 分。
- 全价营养包 B 为标准食谱必配项。数据库说明明确包含 Omega-3、鱼油、藻油、DHA、EPA 或脂肪酸时，可确认覆盖必需脂肪酸来源；但营养包仍在烹饪后拌入，不计入 A 包食材重量、宏量营养、能量密度、食材比例或烹饪参数。
- 食材结构分类与营养数值覆盖分开处理：名称或食材库能明确判断牛肉、牛肝等类别时必须计入结构比例；营养数值缺失时单独提示覆盖不完整，不得把明确类别显示为0%。
- 中文结果必须保留每个风险代码的具体标题、原因和调整建议，不能用“营养检查结果”或“能量检查结果”等通用占位文案覆盖原结论。
- Fresh Check 产生的每个 finding code 必须具有中、英、德、法、西、意、日、韩八种人工审核模板；新增 code 未配置模板时必须返回 `fallback` 和明确的本地化错误码，禁止用通用模板伪装成 `translated`。
- `score_details` 与 AI 食谱的 `validation_details` 必须只传递稳定 code、数值和 facts，并由本地化层渲染；所有扣分 code 都必须有八语言 UI 映射。未知扣分 code 必须显示本地化异常，且必须使整个 presentation 的 `translation_status` 变为 `fallback` 或 `partial`。
- 每日营养建议属于基于 RER/MER、体重、年龄及活动水平的日常喂养参考，应提示结合 BCS 和实际变化持续调整；疾病、特殊生理阶段或特殊营养需求必须建议咨询兽医。
- 普通幼犬已使用幼犬阶段标准时不扣宠物适配分；只有过敏冲突、健康记录、特殊生理阶段或关键档案缺失才扣分，并返回可见依据。
- 4个月以下幼犬以 `3 × RER` 作为初始能量估算，不再叠加普通活动系数；活动量保留为后续观察项。幼犬目标体重低于当前体重时标记档案冲突，不参与减重推导。
- AI 营养推荐与鲜食验证共用上述 RER/阶段/活动/绝育/目标修正逻辑。AI 推荐必须按每个候选食谱自己的食材能量密度反推每日克数和每餐克数，不得再使用“体重 × 固定克数系数”作为完整主食建议。
- AI 营养分析顶部的“每日总量、每日食材占体重、推荐食谱能量密度”是宠物档案参考目标：幼犬按体重 8%、成犬 5%、老年犬 4.5%计算参考食量，再用已经完成活动、绝育、喂养目标和目标体重修正的每日能量除以参考食量得到推荐能量密度。候选食谱详情仍按该食谱真实能量密度反推实际所需克数；两个口径必须分别命名和展示，不能用首个候选食谱的密度覆盖档案参考目标。
- AI 候选食谱的匹配分必须受鲜食验证的确定性长期适宜性和食量可执行性约束；能量不足、数据覆盖不足或所需食量过大的候选不得显示为高适配推荐。
- AI 食谱详情页雷达图下的“注意事项”必须与当前候选食谱的同一次确定性验证报告同源，只展示雷达得分低于或等于85分的直接评分维度、分项得分和实际扣分原因；长期适宜性是其他维度的最低分汇总，不在注意事项中重复。能量满足度因食量可执行性扣分时，必须同时显示当前食谱能量密度、页面推荐能量密度、所需食量和参考食量；不得混用犬种档案或 AI 生成的通用注意事项。
- 宠物适配性扣分必须返回并展示实际分项：分项名称、已得分/满分和评分事实。生命阶段扣分需显示蛋白质与脂肪适配分；健康约束扣分需显示命中的宠物健康标签，不能回退为“当前食谱在该维度仍有未满足项”。
- A 包食材比例不足 100% 时，食材克数按 A 包内部比例归一；B/C 包不参与食材能量的部分必须保持明确排除，不能让页面显示克数与实际烹饪克数使用不同口径。
- 能量需求满足度同时取“热量匹配分”和“食量可执行分”的较低值。页面必须展示每日总克重占体重比例、每餐克重、能量密度和估算含水率；热量足够但食量过大时仍判为需要调整。
- 食量可执行性采用 HeyboPet 产品级护栏：幼犬每日食材总重参考值为当前体重的8%，成犬5%，老年犬4.5%；只有比参考食量超出20%以上才提示“每日食量过大”并开始平滑扣分。建议必须先比较当前能量密度与参考体积所需密度：已经达标时只建议缩减总量，不得继续要求提高密度。这是筛查阈值，不是兽医处方。
- 含水率仅在食材库水分数据覆盖达到80%时显示；覆盖不足时隐藏该指标，不用占位符冒充估算结果。
- WSAVA指出公式只能作为初始估算，犬只实际能量需求可能有约30%的差异。结果页必须提示结合连续体重、BCS和生长曲线调整，不能把一次公式结果当作固定处方。

## 宠物适配性平滑评分

宠物适配性采用七项加权模型：年龄与生命阶段20分、体型与成长约束10分、体重/目标/能量15分、活动/绝育/喂养目标10分、孕哺与恢复状态10分、基础疾病约束20分、过敏与不耐受15分。页面必须展示每项得分、依据和改善建议。

- 阶段蛋白质与脂肪达标率、能量偏差、疾病相关脂肪/碳水/内脏偏差按连续比例计分，避免固定档位跳变。
- 当前体重、目标体重、活动水平、绝育状态和喂养目标同时用于能量估算；其中能量匹配只占适配性的15分，完整能量结果仍由独立的“能量需求满足度”表示。
- 命中过敏或食物限制时该子项为0，并保留红色安全风险。
- 孕期、哺乳期、术后和病后恢复分别计入生理状态子项。
- 肾脏、心脏及泌尿问题所需的磷、钠等数据不足时不得宣称完全适配，必须提示“建议听从专业医师建议”。
- 该权重是HeyboPet产品级可解释评分，不是医疗诊断或FEDIAF官方评分公式。

## 参考阈值

宏量营养阶段最低值采用 FEDIAF 2025 犬用完整与均衡宠物食品指南的每 1000 kcal ME 指标：成年维持蛋白质 52.1g、脂肪 13.75g；14 周龄前生长蛋白质 62.5g、脂肪 21.25g；14 周龄后生长蛋白质 50g、脂肪 21.25g。

食材重量结构阈值是 HeyboPet 产品级鲜食结构护栏，不是 FEDIAF 医疗或完整营养标准。结果页必须将两者分别展示。

### 食材重量结构分段

动物性食材包括动物肌肉与内脏，内部兼容字段仍为 `animal_protein_pct`：

- 低于 40%：提示低于 45%–65% 的常规推荐范围太多，需要重点检查蛋白质、脂肪、必需氨基酸和能量密度能否满足宠物需求；结构评分扣分。
- 40%–45%：提示低于 45%–65% 的常规推荐范围，可以接受，但应通过营养计算确认，重点检查能量密度；不自动扣结构分。
- 45%–65%：常规推荐区间。
- 高于 65% 至 75%：提示高于 45%–65% 的常规推荐范围，可以接受，属于高动物性食材结构，不一定有问题，但应检查脂肪、钙磷、内脏和总能量是否超标；不自动扣结构分。
- 超过 75%：提示高于 45%–65% 的常规推荐范围太多，容易挤压纤维和其他食材空间，也可能导致脂肪、磷、铜或维生素 A 过高；结构评分扣分。

淀粉类碳水食材：

- 低于 10%：提示碳水比例太低，可以作为低碳水宠物零食配方，不可以长期作为主食食谱配方；不自动扣结构分。
- 10%–15%：提示碳水比例偏低，建议增加淀粉类食材到常规推荐区间；不自动扣结构分。
- 15%–35%：常规推荐区间。
- 高于 35% 至 45%：提示碳水比例偏高，检查蛋白质密度和总能量能否满足宠物营养需求；结构评分扣分。
- 超过 45%：提示碳水比例太高，不建议作为常规犬鲜食结构，会稀释动物性营养；加重结构扣分。

非淀粉果蔬：

- 低于 5%：提示纤维和食材多样性不足，并观察宠物粪便情况；不自动扣结构分。
- 5%–10%：提示纤维摄入偏低，建议增加非淀粉类果蔬；不自动扣结构分。
- 10%–25%：常规推荐区间。
- 高于 25% 至 30%：提示纤维摄入偏高，需要检查能量密度和粪便情况；结构评分扣分。
- 超过 30%：提示纤维摄入过高，容易导致日粮体积过大、能量密度下降；加重结构扣分。

水果计入非淀粉果蔬总量，同时单独统计 `fruit_pct`。水果建议只占总配方约 0%–5%；超过 5% 时独立提示并扣分，主要果蔬来源应是低淀粉蔬菜，而不是高糖水果。上述结构提示不能替代宏量营养、微量营养和能量计算；低碳水、低果蔬或高动物性结构本身均不直接等于健康或不健康。
