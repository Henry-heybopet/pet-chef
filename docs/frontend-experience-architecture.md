# Heybo Pet 前端体验层架构

## 目标

前端体验层需要支撑一条清晰的用户闭环：

```text
建档 -> 推荐 -> 购买 -> 制作 -> 喂食反馈 -> 健康追踪
```

第一版优先保证用户能完成宠物建档、食谱推荐、设备绑定和鲜食制作。第二版在此基础上补齐商城、健康趋势、消息触达和更完整的账号自助管理。

本次整理只定义模块边界和用户旅程，不修改现有页面入口、样式和运行依赖。后续主线程可逐步把现有组件接入 `frontend/src/modules/appModules.js` 与 `frontend/src/modules/userJourney.js`。

## 模块总览

| 模块 | 第一版范围 | 第二版范围 |
| --- | --- | --- |
| 用户注册/登录 | 手机号或基础账号登录入口、登录态判断、隐私协议确认、未登录拦截规则。 | 微信/Apple 登录、账号注销、Token 刷新失败恢复、多设备登录管理。 |
| 宠物档案 | 犬只基础档案：品种、年龄、体重、健康偏好；为推荐提供标准输入。 | 多宠物管理、猫入口、体况评分、疾病史、过敏源、阶段性目标。 |
| 食谱 | 基于宠物档案展示推荐食谱、食谱列表、食材配比、营养说明和选择动作。 | 周期计划、动态替换食材、库存感知推荐、A/B 推荐解释和收藏。 |
| 鲜食制作 | 把选定食谱转成制作流程，展示制作步骤、烹饪状态和完成结果。 | 远程制作预约、失败恢复、制作历史复用、多人家庭共享制作记录。 |
| 商城 | 第一版只预留入口、购物清单和食材订购触点，不阻塞核心制作闭环。 | 购物车、订单、支付、订阅、地址、售后和食材补货提醒。 |
| 设备管理 | 设备添加、绑定状态、在线状态、基础控制入口，与鲜食制作流程打通。 | 多设备管理、家庭共享、固件升级、设备异常诊断、售后工单入口。 |
| 健康追踪 | 第一版可先记录喂食反馈的基础数据结构，页面入口可延后。 | 趋势图、体重/便便/食欲记录、健康报告、异常提醒、推荐反向调参。 |
| 消息中心 | 第一版仅预留通知类型和路由，不作为核心交付。 | 系统通知、制作完成提醒、健康提醒、订单物流、活动和售后消息。 |
| 账号设置 | 基础个人信息、协议入口、退出登录。 | 手机号更换、隐私权限、家庭成员、收货地址、订阅管理、账号注销。 |

## 模块职责

### 用户注册/登录

负责管理 Heybo 用户身份和登录态，是所有私有数据模块的前置依赖。第一版需要让用户能稳定进入 App、确认协议，并为宠物档案、设备绑定和制作记录提供用户上下文。第二版扩展第三方登录、账号安全和自助注销。

### 宠物档案

负责沉淀宠物的基础营养输入。第一版聚焦犬只，以品种、年龄、体重和基础健康偏好驱动食谱推荐。第二版支持多宠物、猫入口、疾病史和长期目标，使推荐系统能够从一次性输入升级为持续画像。

### 食谱

负责承接宠物档案并输出可选择的鲜食方案。第一版包含推荐列表、食谱详情、食材配比和选择动作。第二版扩展周期喂养计划、食材替换、收藏和更细的推荐解释。

### 鲜食制作

负责把用户选择的食谱转化为可执行制作流程。第一版需要覆盖制作确认、步骤展示、设备状态联动和结果反馈。第二版增强预约、失败恢复、历史复用和家庭协作。

### 商城

负责食材购买和订单体验。第一版只保留食材订购入口、购物清单和订单路由占位，避免商城能力阻塞建档到制作的核心闭环。第二版补齐购物车、支付、地址、订阅和售后。

### 设备管理

负责鲜食机从添加到可用的体验。第一版覆盖添加设备、绑定关系、在线状态和基础控制入口。第二版支持多设备、家庭共享、固件升级、异常诊断和售后联动。

### 健康追踪

负责把喂食结果反馈为可持续的健康数据。第一版先定义喂食反馈和健康记录入口，为后续数据回流预留结构。第二版提供趋势图、健康报告、异常提醒，并反向影响食谱推荐。

### 消息中心

负责集中承载通知和待办。第一版预留路由和消息类型，暂不进入核心交付。第二版承接制作完成、设备异常、健康提醒、订单物流和运营活动。

### 账号设置

负责用户自助管理。第一版包含个人信息、协议入口和退出登录。第二版扩展手机号更换、隐私权限、家庭成员、地址、订阅和账号注销。

## 前端代码组织建议

`frontend/src/modules/appModules.js` 维护模块定义数组，字段统一为：

- `id`：稳定模块标识，供路由、权限、埋点和文档引用。
- `title`：中文显示名。
- `phase`：计划阶段，当前使用 `v1` 或 `v2`。
- `status`：模块状态，当前使用 `planned` 或 `in-progress`。
- `dependencies`：前置模块 id 列表。
- `primaryRoutes`：模块主路由或未来路由占位。

`frontend/src/modules/userJourney.js` 维护主用户旅程定义。旅程步骤按建档、推荐、购买、制作、喂食反馈、健康追踪排序，每一步关联 `moduleId` 和主路由，方便后续把页面、埋点和引导状态挂到同一份定义上。

## 主线程集成点

- 在路由层读取 `appModules`，逐步把现有页面映射到模块主路由。
- 在首页或导航层基于 `phase` 和 `status` 控制入口展示。
- 在登录态、宠物档案和设备状态稳定后，为 `primaryUserJourney` 增加步骤完成状态。
- 在埋点层使用模块 `id` 和旅程步骤 `id` 统一事件命名。
- 在商城和健康追踪进入第二版开发前，先复用当前定义补齐页面骨架和空状态。
